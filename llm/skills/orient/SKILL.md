# Orient

Use this workflow when starting in a new repo, subsystem, or poorly understood task area.

## Steps

1. Identify project type, package managers, key manifests, and likely entry points.
2. Find build, test, lint, typecheck, and run commands from project files before guessing.
3. Map the relevant code paths and ownership boundaries for the user's goal.
4. Note conventions that are not obvious from filenames.
5. Return only actionable context: files, commands, constraints, and recommended next steps.

## Output

- Project shape.
- Relevant files and why they matter.
- Available commands.
- Constraints, risks, and next step.
